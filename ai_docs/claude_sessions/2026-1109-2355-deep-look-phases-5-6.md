# Deep-look plan: Phases 5 and 6 (lock waits, replication, shutdown, NaN)

Session: `2c5b1603-fa95-4c81-b037-0bcdc19533ac` (continues
`2026-1109-2330-deep-look-phases-2-to-4`).

## What landed

- **D-33, interruptible writer-lock waits** (`7d48f30`). Single-writer mode
  now holds a one-slot write semaphore in the engine (`acquireWrite` /
  `releaseWrite` / `kvUpdate`) around every btypedb write transaction. The
  wait honors the statement's context; `WriteTxnCtx`,
  `WriteTxnSerializableCtx`, `BeginCtx` and `BeginSerializableCtx` are new,
  and the SQL layer's writes and `BEGIN` use them. A timed-out or canceled
  write never runs. No btypedb release was needed.
- **D-36, NaN and -0 in float columns** (`4cb9c68`). The tuple encoding
  canonicalizes NaN to one bit pattern that sorts above +Inf (Postgres
  order) and keeps -0's sign; hash joins and grouping treat NaN = NaN, as
  Postgres does.
- **D-35, graceful shutdown** (`b3bd2db`). `pgwire.Server.Shutdown(ctx)`:
  stops accepting, wakes idle readers, lets running statements and
  buffered pipelines finish, sends FATAL 57P01 to each connection at a
  message boundary, and on ctx expiry cancels statements and closes
  connections. `bytdbd -shutdown-grace` (default 10s); a second signal
  stops immediately.
- **D-34, replication** (`4d52dcc`). Generation names lead with a sequence
  number (`g0000000000000042-<ts>-<rand>`, one past the store's largest at
  roll time) that orders restore and pruning; legacy timestamp names count
  as 0. `Status.Sealed`, `Status.LagBytes`. Per-operation store deadlines
  scaled by payload (`OpTimeout` 30 s + n / `MinTransferRate` 64 KiB/s).
  Size-tiered chunk merging (`MergeChunks`, default 8, never past
  `MaxChunkBytes`, parts deleted after a 10-minute grace). Restore
  downloads 6 chunks at a time, writes in order, and re-lists once when a
  chunk vanishes. s3 `SessionToken`; a truncated list page without a
  continuation token is an error.

## Decisions

- **D-33 without btypedb.** The plan assumed btypedb `BeginCtx`/`UpdateCtx`
  and a btypedb tag. A semaphore in the engine does the same job (btypedb's
  writer mutex is then never contended in single-writer mode), keeps the
  change in one repo and avoids a release the user has not approved. OCC
  mode has no writer lock to wait for, so it skips the slot.
- **Sequence number in the name, copy in the manifest.** The plan said
  "store seq in the manifest and sort on it". Unmanifested generations need
  an order too (pruning counts them), and a listing alone should decide,
  so the number leads the name; the manifest's `seq` is informational. The
  "g" prefix makes every new name sort after every legacy one, in a plain
  listing as well.
- **First roll needs a listing.** Without one the replicator cannot know a
  number above everything in the store, so the ship fails and retries. A
  later roll in the same process falls back to its own last number plus
  one, which is sound because one replicator owns a prefix.
- **Merging instead of BackupTo snapshots.** A snapshot is a different
  file from the log, so log ranges shipped after it would not continue it.
  Tiered merging of the current generation's own chunks needs no new
  restore format: restore already takes the furthest-reaching chunk at each
  offset (D-05). A run too big to merge pins only its first chunk, so small
  chunks behind a big one can still merge later.
- **Restore keeps its signature.** It uses the default deadlines and 6
  workers; no `RestoreOptions` until someone needs to tune them.
