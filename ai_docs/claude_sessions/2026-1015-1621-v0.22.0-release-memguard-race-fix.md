## 2. Full suite under -race: memguard test hook race

The repo has no CI config. "Full suite" was taken as `go test -race
-count=1 ./...` in the root and pgwire, plus `go vet` and a compile-only
`go test -run '^$'` in bench, which has only benchmarks.

**Failure:** `TestMemoryCeilingRefusesGrowth` and
`TestMemoryCeilingAuto` reported DATA RACE in the full root package run.
Each passed when run alone, and so did the `TestMemoryCeiling*` group,
even with `-count=5`.

**Cause:** `memGuard.sample` was a plain `func` field. `fakeHeap` in
`memguard_test.go` assigns it in the middle of a test. When a check finds
the heap over the ceiling, `resample` starts a forced-GC goroutine that
calls `resample` again and reads `g.sample`. That goroutine can outlive
the check that started it, so the test's next `fakeHeap` write raced its
read. Production never writes the hook after `Open`, so this is a test
race only. **v0.22.0 needs no patch.**

**Fix:** `sample atomic.Pointer[sampleFunc]` with a named
`type sampleFunc func() (live, gomemlimit uint64)`. `resample` loads it
and falls back to `runtimeMemSample` when it is nil, and `fakeHeap`
stores through it. The field comment says why it is atomic. After the
fix, `go test -race` passed in every root package, in pgwire and in
bytdbd, and bench compiled. Not tagged, because the fix touches only the
test hook.
