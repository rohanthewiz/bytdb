# N-054: duplicate relations are 42P07, not XX000

Session: `10e25b82-be09-499d-8c4c-c13f4acd0ec2`. Loaded the previous
session (`2026-1111-1759-numeric-type-n048`) and the living list. Asked
what to do next, I recommended N-054 (the only medium-value Open item),
then a release that carries N-048 and this fix together. The user said
"do it". Nothing tagged.

## The defect, wider than filed

N-054 named CREATE TABLE only. Every duplicate-relation error fell
through `pgwire/errors.go` to XX000:

| Statement | Old message | Old code |
|---|---|---|
| CREATE TABLE onto a table | `table already exists` (+ table field) | XX000 |
| CREATE TABLE onto a view/sequence | `relation "x" already exists` | XX000 |
| CREATE VIEW onto a table/sequence/view | `relation "x" already exists` | XX000 |
| CREATE SEQUENCE onto any relation | `relation "x" already exists` | XX000 |
| CREATE INDEX onto an index of the same table | `index already exists` (+ fields) | XX000 |
| ALTER TABLE RENAME onto a taken name | `relation "x" already exists` | XX000 |

Postgres 16 sends 42P07 `relation "x" already exists` for all of them
(checked in `bytdb-numeric-pg` on 55432).

## Fix

- `err.go`: new sentinel `ErrRelationExists` and `errRelationExists(name)`
  built on `KindErr`, the D-56 pattern. No fields of its own. The DDL
  entry points' wrappers still add `op`/`table` context, so the wire
  Detail reads e.g. `op: create table, table: t`, which is bytdb's normal
  convention.
- All seven sites use it: `ddl.go` (CreateTable x2, RenameTable),
  `seqobj.go`, `view.go` x2, `index.go`.
- `pgwire/errors.go`: `sqlstateOf` maps the sentinel to 42P07. `sqlstate`
  has a text fallback (`relation "` … `" already exists`), placed ahead
  of the 42710 `constraint … already exists` case, so a relation named
  `constraint_log` isn't claimed as a duplicate constraint.
- Checked first that no sibling project (gonotes, go-daw, mini, camctl,
  ccgrand) matches on the old message text. They probe the catalog or
  only mention it in comments.

## Verification

- `sql/difftest/corpus/78_duplicate_relation.sql`: 9 `@error 42P07`
  entries plus two queries showing nothing changed. It passes against
  PG16, and with the pgwire mapping stashed it fails 9 times with XX000.
- `pgwire` `TestDuplicateRelation` (pgx, code + exact message, plus the
  IF NOT EXISTS forms still skipping), `TestSQLStateMapping` rows
  (including the `constraint_log` ordering case), `sql`
  `TestSentinelErrors` rows (`errors.Is` + message for each kind).
- `/verify`: scratch bytdbd + pgx client, 18/18 (the nine duplicates over
  the simple and the extended protocol, code + exact message). The
  table row survived and `create table if not exists` still skips. A
  probe of CREATE TABLE inside BEGIN hit bytdb's documented 25001 (DDL
  refused in a block) before the duplicate check; that is existing
  behavior, not this change.
- Race suite for root and pgwire green. staticcheck v0.8.2 is clean via
  `go run honnef.co/go/tools/cmd/staticcheck@v0.8.2` (the PATH binary is
  built with go1.23 and can't load go1.26 modules). gofmt clean.
- Docs: README sentinel table row, the bytdb skill's sentinel list, and a
  `docs/gotchas.md` Schema-change bullet: index names are per table
  (verified with a throwaway test that two tables can share an index
  name and an index can share a table's name).

## Release-note items (on N-054's Closed entry)

Duplicate-relation errors are 42P07 (were XX000). CREATE TABLE's and
CREATE INDEX's messages are now `relation "x" already exists`. New
sentinel `bytdb.ErrRelationExists`. With N-048 on main and untagged, the
next release (minor: new API and behavior changes) carries both.
