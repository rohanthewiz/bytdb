## Verification

- `sql/difftest/corpus/77_numeric.sql` (40 statements) matches Postgres
  16.15 (Docker `postgres:16`, container `bytdb-numeric-pg` on 55432 —
  left running) exactly. difftest now compares columns both sides type
  numeric as exact text (`clsNumericExact`), not via float64; the
  stale `@notype` on `75_functions.sql`'s round/trunc line is gone.
- Unit/integration: `decimal_test.go` (expected values are PG's
  output), `tuple` `TestDecimalForms` + fuzz seeds/generator, root
  `numeric_test.go`, `sql/numeric_test.go`, pgwire
  `numeric_internal_test.go` (vs `numeric_send` hex) and
  `numeric_test.go` (pgx end to end), `stdlib/numeric_test.go`, shell
  `TestDumpNumeric`. Race suite, staticcheck v0.8.2, gofmt clean.
- `/verify`: bytdbd + pgx client, 15/15 checks over simple and extended
  protocols.
- ~25 existing tests that pinned float8 answers for decimal literals or
  avg(int) were updated to Postgres's answers (each checked in PG).

## Gotchas learned

- pgx's binary numeric decoder drops a zero's display scale (ndigits 0),
  so `0.00` scans as "0" from real Postgres too; tests pin that.
- `bindArg` recursed forever on a kind `NormalizeValue` passes through
  unchanged (Decimal hit it); now guarded by a same-type check.
- `reflect.DeepEqual` on Decimals needs the canonical zero (`mk`).
- `pkill` of the scratch bytdbd did not always land before the restart;
  the second server then could not bind and the client hit the old
  in-memory state. Check `pgrep` / `nc -z` before reusing the port.
- Performance: shared pow10 table + allocation-free small `Cmp` +
  numeric mantissa decode + in-place `decimal.Sum` took sum+avg over
  100k rows from 31 → 18 ms (float8: 11.7) and a cross-scale filter
  from 45 → 18 ms (`sql/numeric_bench_test.go`).

## Release-note items (on N-048's Closed entry)

Decimal literals are numeric (OID 1700) — `select 1.5`, `7.0/2`,
`avg(int_col)` return numeric (Go: `bytdb.Decimal`, driver: string);
`2.5::int` is 3; `::numeric(p,s)` rounds; `bigint out of range` /
`division by zero` are 22003 / 22012 (were XX000).
