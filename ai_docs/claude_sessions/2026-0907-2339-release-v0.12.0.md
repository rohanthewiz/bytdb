## Why a minor bump and not a patch

Both phases change behavior that callers can observe, in opposite
directions, which is what took this past a patch:

- **Phase 2 refuses statements that used to run.** `ADD COLUMN ... DEFAULT`
  now stops at `Engine.BackfillLimit` (default `1_000_000` rows). The
  backfill holds every rewritten row live until commit, so an unguarded
  migration on a large table is an OOM kill part-way through, not merely a
  slow statement — hence a refusal rather than a warning. Embedders raise
  or disable the cap with `SetBackfillLimit`.
- **Phase 3 accepts statements that used to error.** `CREATE TABLE` /
  `CREATE SEQUENCE ... IF NOT EXISTS` now consult the whole relation
  namespace (tables, sequences, views) instead of only their own kind, so
  the clause swallows the collision it promises to.

## The pgwire tag line had a gap

The plan's premise was that pgwire sat at v0.11.0. It did not: its last
tag was **`pgwire/v0.9.1`**. Commit `7ad2c0d` ("pgwire: bump bytdb to
v0.11.0") moved the pin on main but was never tagged, and v0.10.0 was not
tagged either — two pgwire releases were sitting untagged on main.

Tagged `pgwire/v0.12.0` rather than `pgwire/v0.10.0`, because every earlier
pgwire tag matches its bytdb tag (v0.7.0, v0.8.0, v0.9.0, v0.9.1) and that
lockstep is plainly deliberate. The cost is that `pgwire/v0.10.0` and
`pgwire/v0.11.0` are now permanent gaps in the sequence; the alternative
was a permanent version skew between the two modules, which is worse for
anyone reading a `go.mod`. Offered to backfill the two missing tags at
their commits; not requested.

The stale premise came from the **project memory index**, which recorded
"latest tags … pgwire v0.11.0" for a tag that never existed. Corrected —
this is the second consecutive session where that one line carried a false
premise into the work, after last session's "three comb follow-ups
pending" entry. The `[[verify-carried-items-before-repeating]]` memory
exists for exactly this and worked as intended: the tag list was checked
against `git tag` and `git ls-remote` before acting, not assumed.

### Deliberate non-goals (declined, not dropped)

- **Unindexed FK columns scan the child table per check.** Planner-driven
  FK enforcement with no index requirement; documented in the skill's
  gotchas with the workaround ("index the child FK columns"). A design
  property, not a task.
- **Embedded Engine one-shot writes surface `ErrTxConflict` raw.** The
  caller writes the retry loop, same contract as `WriteTxn`; documented in
  `docs/concurrency.md`.
- **Correlated ON conjuncts and function-wrapped correlated predicates
  evaluate per row.** Full Postgres-style decorrelation was considered and
  rejected at `2026-0805-1603`; rewrite as JOIN for large outer sets.
- **`WriteString` lint hints in test files.** Test readability is worth
  more than the allocation.
